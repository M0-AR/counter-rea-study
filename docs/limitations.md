# Limitations and threats to validity

## 1. Fixture minimality

Each format has one small, readable fixture generated by
`artifact/scripts/make_fixtures.mjs`. The fixtures isolate one mechanism at a
time; they are not representative samples of real applications. The study
therefore reports **case-level paired ratios**, not population estimates. In
particular:

- The JavaScript app is a few hundred bytes; a real bundle would have more
  symbols, dynamic imports, and framework behavior.
- The WASM module has one export; the export-decoy flood is easy to see.
- The SQLite database is 12 KB; the trap is one table with three virtual
  columns.
- The PCAP has one baseline packet; the protected file has 161 packets.
- The ELF is a small static binary; the protector appends a large section but
  the analyzer still reads only headers.

A different fixture can move a factor by orders of magnitude. The WASM result
is the clearest example: our 21.5 MB representation is below REA’s 32 MiB cap,
while BLA’s 2.5 KB smaller module is rejected. The PCAP result is query-shaped
by a factor of 151× on the same file.

## 2. Single versions and single tools

- One BLA version (`3.2.5`) and one REA version (`6.9.0`) are tested. Budget
  values and defaults change; the paper does not claim version-independent
  constants.
- One protector intensity is used for the main table (`bankrupt`). The
  intensity sweep covers JS and WASM only.
- TShark 4.0.17 is the Docker version; BLA’s own validation used 4.4.19.
  Packet parsing and JSON size can differ.
- No Erlang runtime is installed, so BEAM functional equivalence is untested.
  The BEAM result is a REA admission result, not a runtime result.
- No Ghidra, Hopper, Frida, LLDB/GDB, Rizin, or JADX is installed. The study
  evaluates REA only.

## 3. Token metric is an estimate, not a billed invoice

REA’s `--token-count` uses `tokenx` 1.3.0, an approximate tokenizer. It is not
the tokenizer of any particular LLM. The study reports it because it is the
unit REA itself exposes. The `cl100k_base` sensitivity check shows that
individual factors can move by 2–7× (EVM 978.6× vs 6732.3×; WASM 2077.21× vs
3122.9×; PCAP 14.37× vs 25.4×) while the rank conclusion is unchanged.
Neither unit is a dollar cost.

## 4. No live LLM agent

No LLM API key was available. The study measures analyzer token/byte cost, not
whether an LLM agent would give up, route around the trap, or hallucinate an
answer from decoys. The epistemic-hazard hypothesis is discussed but not
tested. The `agent_cost` experiment remains design-only in `PROTOCOL.md`.

This is a real limitation: a 2077× token increase may still fit in a 1M-token
context, and a 1.29× increase may be irrelevant if the agent never opens the
trap table. The paper does not infer agent behavior from token counts.

## 5. Absolute-path dependence

REA evidence includes absolute paths. The host path is longer than the
container path, so identical artifacts produce slightly different token counts
(SQLite 1,281 vs 1,308 baseline; 1,575 vs 1,684 protected). The canonical run
is Docker; the discrepancy is a measurement artifact. Ratios are rounded to two
decimals and should not be treated as exact beyond that.

## 6. Comparison with BLA is not a controlled replication

BLA’s showcase fixtures are not included in the upstream repository at the
pinned commit; its `docs/redteam/empirical-rea-validation.json` contains BLA’s
own generated fixtures and results. We did not regenerate BLA’s exact cases.
Therefore:

- The README-vs-benchmark disagreement is a **same-commit, same-code** audit
  and is directly checkable.
- The claimed-vs-measured factor comparison is **not** a same-fixture
  replication: the claimed factors are BLA’s modeled estimates, while the
  measured factors come from our independent fixtures.
- The finding is about external validity and query dependence, not “BLA’s
  exact numbers are false.” BLA’s own live-REA JSON is credible for BLA’s
  fixtures.

## 7. Small sample and statistical caveats

Eight successful CLI cases are used for the claimed-vs-measured correlation.
This is not a random sample, and the bootstrap interval is wide
([−0.81, 0.76]). The correct conclusion is “no detectable positive
association in this sample,” not “the true association is zero.” The
log-log slope (0.018) is descriptive. The geometric means (1003× claimed vs
36× measured) are dominated by the large PTX and SQLite claimed values.

The 12 cases are also not independent in a strict sense: the claimed factors
come from the same estimator family, and several formats share protector
machinery.

## 8. Hard denials are not cost amplification

When REA exits 1, the token count is the refusal payload (138–4,168 tokens),
not the cost of analyzing the protected artifact. Combining refusals and
successes into one “amplification” average would be wrong. The paper separates
amplified, neutral, and refused outcomes, and reports the ASAR override
separately.

A hard denial can be a defender win (the analyzer sees nothing) or a
defender loss (the user’s own tooling breaks, or the analyst simply uses a
different tool). The study does not resolve that trade-off.

## 9. Verifier and functional-check scope

`bla verify` is structural and self-referential; it is not an independent
oracle. The benchmark’s `functionalCheckPassed` is mixed: it executes JS and
ASAR but only checks headers/prefixes for ELF, PTX, PCAP, and EVM, and falls
back to an arbitrary WASM export if the expected one is missing. Neither
surface establishes runtime equivalence. Our independent checks cover JS, ASAR,
SQLite, safetensors, GGUF, EVM, PCAP, PTX, ELF, and PYC; BEAM is untested.

## 10. Generalization

The study supports a conditional claim: **budget traps are real but
query-shaped and fixture-dependent**. It does not support a universal
multiplier, a claim that every BLA format works, or a claim that BLA is
worthless. The defender-economics result is similarly conditional: four
amplified cases, three neutral cases, five refusals, and one override. A
deployment decision needs the vendor’s actual artifact and the defender’s
threat model.
